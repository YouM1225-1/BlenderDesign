## 2. 最终修复轮

| ID | 攻击面 | 修复结果 |
|---|---|---|
| C-01 | `session.json` 写入中 `fchmod` / `fdopen` 失败泄漏 fd | 所有失败路径关闭 fd；回归以 fd 数量验证 |
| C-02 | session、请求或响应为深层嵌套 JSON，触发 `RecursionError` | discovery 隔离坏 session；wire parser fail-closed，不让异常越过协议边界 |
| C-03 | 孤立 Unicode 代理项或超长 `id` / `token` / `method` | 编码与文本字段均有明确边界；无效请求返回有界错误帧 |
| C-04 | `now == deadline` 仍被队列接受 | deadline 使用闭区间过期语义；边界测试已固定 |
| C-05 | Audit 初始化失败泄漏本机路径或返回非结构化异常 | 统一 `AUDIT_UNAVAILABLE`、`retryable=true`；消息不含内部路径 |
| C-06 | Audit 序列化或锁等待越过 postlude 预算 | audit 使用独立、单一绝对 deadline，最长 1 秒；失败可覆盖业务结果并 fail-closed |
| C-07 | status 提交 futures 时已耗尽预算 | 提交和聚合共用同一 deadline；未提交/未完成项进入 `partial/skipped_count` |
| C-08 | `instances()` 与随后读取的 `ScanStats` 来自不同并发扫描 | `instances_with_stats()` / `find_with_stats()` 原子配对快照 |
| C-09 | 已有会话丢失 handler/timer 后 driver 不自愈 | `start()` 会补回缺失注册；注册失败仍逆序回滚本次新增项 |
| C-10 | 单个 socket close 失败跳过同组资源；第一次 join 后才 close transport | 每项回收独立尝试；transport close 后再做第二次 1 秒 join |
| C-11 | BridgeClient 只给 socket I/O 计时，编码、解码、响应验证可越界 | 全调用唯一 absolute deadline 覆盖 encode/send/recv/decode/validate |
| C-12 | `SessionAuth.verify()` 遇到不可编码字符串抛异常 | 非法字符串返回 `False`，不越过认证边界 |
| C-13 | Bridge 信封合法但 `scene_summary` payload 缺字段或类型错误 | 公共 MCP 边界统一返回 retryable `BRIDGE_UNAVAILABLE`，invalidate discovery，并记录领域错误码 |
| C-14 | status 聚合中的单个 client 抛出非 `BridgeError` 异常 | 该实例映射为 `BRIDGE_UNAVAILABLE` / `disconnected`，继续其他 futures，并 invalidate discovery；异常文本不越过 MCP 边界 |
| C-15 | status 外层 dict 合法但 `scene_path` / `scene_revision` 类型畸形 | per-instance 校验失败只隔离该实例，健康实例仍聚合；统一 `BRIDGE_UNAVAILABLE` / `disconnected` 并 invalidate |
| C-16 | Python JSON 默认接收/发送 `NaN` / `Infinity` / `-Infinity`，`1e999` 解析为无穷 | `_load_json` 以 `parse_constant` 与有限 `parse_float` 拒绝；request/error/success 编码固定 `allow_nan=False`；收发双向回归覆盖 |
| C-17 | accept 后 `setblocking()` / 登记失败，或 rejected socket `close()` 失败时丢失 fd ownership | 局部 socket 在登记成功前由局部变量持有；失败 close 放入 pending-close，I/O 轮次重试；连接数上限 64 |
| C-18 | fd 数字复用把旧连接误当成当前连接；部分 send 低估仍驻留的 frame bytes | `send()` 校验 `_conns.get(fd) is conn`；部分写保持完整 frame 计数，只有整帧出队/drop 才释放；专门回归覆盖 |
| C-19 | 64 个连接各自 32 MiB outbox 形成 GiB 级全局内存压力；入站慢帧洪泛 | 全局入站待收 32 MiB、单请求 64 KiB、单连接 outbox 32 MiB、全局 outbox 64 MiB；超限只标记 closing+wake，由 I/O 线程回收 |
| C-20 | transport close 失败后仍删除 socket/session，driver 状态丢失且无法重试 | `stop() -> bool`；transport 未完全关闭时跳过 unlink/rmdir，driver 保留 session，面板显示重试，下一次 start 先清旧 session |
| C-21 | 缺失/boolean/string `v` 被误报为版本不匹配；合法 mismatch 与 malformed 混淆 | 仅“存在且 exact integer、值不等于 1”映射 `ENVELOPE_VERSION_MISMATCH`；其他响应版本形状统一 retryable `BRIDGE_UNAVAILABLE` |
| C-22 | audit 将 numeric JSON-RPC id 字符串化，或 write/flush/close 后超出 postlude 仍报告成功 | `request_id` 保留 string/integer 原类型；每个 I/O 阶段完成后再次检查同一 absolute deadline，失败覆盖为 `AUDIT_UNAVAILABLE` |
| C-23 | NUL 路径在 `Path.resolve()` 中抛 `ValueError` 越过 PathPolicy 边界 | `ValueError`/NUL 统一映射 `PathDenied`，回归覆盖 |
| C-24 | status/scene 结果串实例或隐式 `dict()` 接受错误 shape；stale cleanup 失败被隐藏 | status response `instance_id` 精确绑定目标；scene `summary` 只接受真实 dict；cleanup 未完成上报 `ScanStats.partial/skipped_count/reason` |

所有源协议修复均同步到 vendored 副本；46 个 Plan Python 文件块与隔离树机械一致性由 [v5 TSV manifest](evidence/2026-08-07-phase0-plan-python-manifest-v5.tsv) 锚定，并另行锚定 pyproject、uv.lock、checks、extension manifest 与 vendor 产物。

## 8. 诚实边界

1. 50 ms 是 cooperative checking budget，不是对单次 Python/bpy/native 原子操作的硬抢占上界。
2. 同步内核 I/O 只能在发起前检查 deadline，并把目标限定为已验证的本机常规文件/目录；不承诺失效网络文件系统或内核卡死下的绝对墙钟。
3. dev/inode 绑定能拒绝检查前换入，但不能从根本上阻止同 uid 恶意进程在 check 与 unlink 之间主动竞态。
4. 官方 MCP 完整通道含任意 Python，按用户明确授权启用；它不满足也不参与自定义系统 G1–G3 证明。
5. 当前模型工具面是否为 26 是宿主上下文验收，不可由磁盘配置或另一 app-server 的 26/26 代替。
6. 官方 manifest 中的 maintainer email 与本机绝对路径是内部部署元数据；若将仓库公开发布，应在发布前单独确认是否改为项目邮箱/相对路径（非代码阻断）。
